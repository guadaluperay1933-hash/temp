# 外汇资金台账（本位币：人民币）

一个文件，16 张表。出纳每天只开【流水录入】一张，其余全部自动。

文件：`外汇资金台账.xlsx`

---

## 一、为什么是重做，不是改

你发来的那套模板骨架是对的（混合录入 + 分表 + 汇报表），但里面有四处是硬伤，
改起来比重搭还费劲，所以按原来的思路重做了一套：

### ① 12 个月里只有 8 月能用

原模板的汇率是**当月精确匹配**：

```
INDEX(参数与汇率!$G$6:$P$17, MATCH(当月1号, 月份列, 0), MATCH(币种, 币种头, 0))
```

那张汇率表里只填了 2026 年 8 月的美元 7.18、港币 0.92，其余 11 个月全空。
于是 8 月以外的任何一笔外币流水 → 汇率空 → 折人民币空 → **所有人民币报表全空**。

新表改成「当月没填，就往前找最近一个填过的月份」，并在核对表点名提醒你补。
先有数，再提醒补数，而不是直接白屏。

### ② 两套人民币口径混在一格里加

原模板的「即时余额(本位币)」：

```
SUMIF(期初余额) × 本行汇率  +  Σ(每笔 × 各自汇率)
```

前半截把期初余额按**这一行**的汇率折，后半截按**各笔当时**的汇率折。
两个口径加在一起，得数在会计上没有含义，而且会随着报表月份来回跳。

新表拆成两栏，各算各的：

| 栏目 | 算法 | 含义 |
|---|---|---|
| 账面人民币成本 | 期初成本 + Σ(原币 × 该笔当时汇率) | 历史成本，汇率再怎么变它都不动 |
| 期末人民币(重估) | 期末原币 × 期末汇率 | 现在值多少钱 |
| **汇兑损益** | 重估 − 账面 | 外币放着，汇率涨跌赚了亏了多少 |

**这一栏是外汇台账跟普通资金台账唯一的区别**，原模板里完全没有。

### ③ 内部转账被算进了收入和支出

原模板的「收支报表」「任意时间段查询」，收入清单和支出清单里**都有「内部调拨」**。
公司把钱从工行转到招行，收入 +5 万、支出 +5 万，两头一起虚增。

新表把「内部转账」「购汇/结汇」设成一个独立属性，单列，不进收支合计。
它的净额不为 0 的部分，就是购汇结汇的**买卖价差**，单独标出来。

### ④ 分类清单里有重复项，金额被算两遍

原模板收入清单：`项目A / 出口业务 / 融资 / 香港业务 / 融资 / 内部调拨 / 出口业务 / 其他业务`
—— **融资和出口业务各出现两次**；支出清单里**行政出现两次**。
这几项在合计里被算了两遍。

新表的类别、项目、币种、往来单位清单全部来自【参数设置】一处，报表自动跟着长；
核对表第 17、18 项专门数重复项。

**另外**：账户清单在原模板里写死在 3 个地方（汇报表 A8:A12、B27:B31、I27:I31），
新增账户不会自己出现；银行子表的 FILTER 里也把账户名写死在公式里。
新表全部改成从【参数设置】动态取，加账户只动一处。

## 三、汇率怎么取（优先级）

1. **实际成交汇率** —— 流水里填了就用它。购汇、结汇、银行有实际成交价的都填这个
2. **当月记账汇率** —— 按交易日期所在月，去【月度汇率】取
3. **往前最近一个填过的月份** —— 当月还没填时兜底，核对表同时点名

示例里 8 月 10 日那笔美元采购填了实际成交价 7.16，其余美元笔用 8 月记账汇率 7.18 —— 你可以直接看到两者的区别。

## 四、自动拆分银行子表

每张子表的 A6 是一条公式：

```
=FILTER(IF(流水录入!$A$6:$S$2005="","",流水录入!$A$6:$S$2005),
        流水录入!$B$6:$B$2005=$B$2, "这个账户还没有流水")
```

`$B$2` 就是这张子表自己的账户名。在流水录入登记完，子表立刻跟着变。
子表顶上还带一条小汇总：币种 / 期初 / 累计收支 / 期末原币 / 期末人民币 / 汇兑损益。

中间那层 `IF(…="","",…)` 是必须的：不套的话，源表空着的格子会被 FILTER 当成 0 搬过来，
日期列显示 `1900-01-00`、金额列显示 `0.00`。

**加一个账户**：① 在【参数设置】账户档案接着写一行；② 右键复制任意一张子表，改表名，把 B2 改成新账户名。
核对表第 6 项会盯着你有没有漏。

## 五、示例数据里故意留的一个坑

示例有一笔 8 月 20 日的**欧元收款 30,000**，而欧元汇率一个月都没填。你会看到：

- 流水那一行的「折人民币」是**空的**，核对列写着 `△EUR 还没填汇率，去【月度汇率】补上就自动算了`
- 账户余额表里欧元户的人民币几列也是**空白，不是 0**
- 核对表第 11 项亮：`在用的外币里，全年一个汇率都没填的个数 = 1`

这不是坏了。**宁可留空，也不瞎按 0 算** —— 画成 0.00 会被读成「这个账户人民币是 0」，
那才是真出事。填上欧元汇率，整条链立刻全通。

示例流水在【流水录入】第 6~23 行（原模板那 15 笔 + 3 笔补充，含一对结汇），
正式用之前整段选中删掉即可，所有报表自动归零。

## 苏姆本位版体检（2026-09-20）

用户把【参数设置】的本位币从 CNY 改成 UZS（苏姆），整套表是按人民币本位做的，
有几处没跟着走。交付件：`苏姆本位资金日记账_2026.xlsx`。

### 三处真 bug

**① 【月度汇率】月末汇率区的币种表头错位**（最要命的一个）

左边「记账汇率」区 B:I 的表头是 `UZS / CNY / USD / EUR / JPY / GBP / SGD / AUD`，
右边「月末汇率」区 K:R 却是 `CNY / USD / HKD / EUR / JPY / GBP / SGD / AUD` ——
错开一位，还多出个左边根本没有的 HKD。

取数公式是 `INDEX(月末汇率区, 0, MATCH(币种, 汇率币种头, 0))`，**按位置取**，
所以在标着「USD」的那一列填月末汇率，系统实际当成 CNY 用，期末重估直接错。
（现在 K 列填的 1 被当成 UZS=1，碰巧没出事，但只要有人去填 L 列就炸。）

改成 `K5==B$5` … `R5==I$5`，右边永远跟左边同一套币种，不可能再错位。

**② 【核对表】第 6 项「子表张数」写死了**

原公式 `=6-COUNTA(账户名)` —— 那个 6 是做模板时的子表数。
现在 5 个账户 5 张子表，它却报「差 1 张」。

改成一行一格用 `ISREF(INDIRECT(...))` 真去数有几个账户确实建了子表
（`INDIRECT` 不能吃数组参数，Excel 勉强、LibreOffice 直接不认，所以用 H 列隐藏辅助列逐个判）。

**③ 【核对表】第 2 项差 0.01**

`期末原币合计 = 期初 + 流水净额` 这条恒等式报 0.01。
原因：【账户余额表】把期初 `ROUND(...,2)` 之后再用，核对公式却拿没 ROUND 的原值比。
这份账的期初带一串小数（`-910124979.333333`、`93650.9982152975`），差额就出来了。
核对公式两边改成同一个口径。
