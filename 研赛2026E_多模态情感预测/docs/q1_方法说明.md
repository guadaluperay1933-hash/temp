# 问题1 方法说明：多模态情感特征提取与时序对齐

> 本文档给论文撰写者使用：下文每一个公式、规则、超参数都与代码（`q1/`、`configs/q1.yaml`）逐项一致，可直接转写进论文。
> 代码入口：`python -m q1.extract`（提取）→ `python -m q1.verify`（核验）→ `python -m q1.visualize_sample`（典型样本图）。
> **重要**：本仓库开发环境无法访问赛题附件1，也无法下载 HuggingFace 模型；第 11 节写明哪些环节已在合成数据上测过、哪些没有。论文中的全部数值（100 条样本汇总表、检出率、时长等）必须来自在真实附件1 上重新运行得到的 `outputs/q1/<run>/` 文件。

## 1 总体方案与处理流程

```
label-100.xlsx（video_id, clip_id, text, label, annotation；只读，原样保留）
        │ 逐行（行序 = 样本序）
        ▼
定位 data/附件1/<video_id>/<clip_id>.mp4 ──→ MD5 校验和、ffmpeg/OpenCV 探测（时长、fps、帧数、分辨率、音轨）
        │
        ├─ 音频流 ─ ffmpeg 解码 → 16 kHz 单声道 ─┬→ 100 Hz × 74 维声学特征（25 ms 窗 / 10 ms 移）
        │                                       ├→ 能量 VAD 有声段
        │                                       └→ 词级强制对齐（wav2vec2-CTC + 自写 Viterbi；不可用时 VAD 比例回退）
        ├─ 视频流 ─ 逐帧解码 → MediaPipe FaceLandmarker → 52 个 blendshape → 35 维 AU 特征（无人脸帧 = 0 行）
        └─ 转写文本 ─ 空白切词 → BERT WordPiece（≤50，整词截断）→ bert-base-uncased 最后一层 768 维
                                   │（每个词元记录所属词下标）
                                   ▼
            跨模态对齐：词级时间区间 ─→ 词元时间区间 ─→ 对齐版（50 个共享位置）
                        语音 100 Hz 帧 / 视频帧 ─→ 80 ms 栅格 ─→ 非对齐版（≤500 个位置）
                                   ▼
features/aligned_100.pkl.gz、unaligned_100.pkl.gz（与附件2 同构）
alignment/<id>.json（逐位置 ↔ 原始素材的时间与帧号）  manifest.csv/.xlsx、manifest_long.csv
run_info.json（环境、版本、全部参数）  logs/extract.log  verification_report.json/.md  figures/typical_<id>.png
```

任何一条样本、任何一个模态处理失败都不中断运行：失败模态整段写 0 行、长度记 0，`status=error` 并写明原因，保证"标注行 ↔ 视频文件 ↔ 特征条目 ↔ 对齐记录"始终一一对应、顺序一致。

## 2 输入与样本定位规则

* 标注表按行读取（`pandas.read_excel(dtype=object)`，列名大小写/空格不敏感）。`video_id`、`clip_id` 可能被 Excel 存成整数或浮点（如 `3.0`），统一转为字符串（整数值浮点去掉 `.0`）。
* 文件定位：先精确匹配 `<video_root>/<video_id>/<clip_id>.mp4`；失败时做宽松匹配（大小写、纯数字去前导零、常见扩展名），并在日志中告警；**样本编号以实际的文件夹名 / 文件名为准**：`id = video_id + "$_$" + clip_id`。
* 标签只读不改：`regression_labels` = `label` 列原值（float32），`annotations` = `annotation` 列原字符串，`classification_labels` = `common.data.reg_to_cls(label)`（y<0→0 Negative，y=0→1 Neutral，y>0→2 Positive）。`annotation` 与由 `label` 推出的类别不一致时只在清单中记录（`annotation_consistent=False`），不改动。
* 极短 / 无效 / 异常片段一律保留，处理规则见第 7 节。

## 3 文本特征（768 维）

| 项目 | 取值 |
|---|---|
| 模型 | `bert-base-uncased`（12 层、隐层 768、12 头、WordPiece 词表 30522，不区分大小写） |
| 输入 | 转写文本按空白切分为词 $w_1,\dots,w_n$；每个词单独 WordPiece 切分为 $P_j$ 个词元 |
| 序列 | `[CLS]` + 保留词的全部词元 + `[SEP]`，后填充 `[PAD]` 至 50 |
| 截断（整词） | 取最大的 $k$ 使 $2+\sum_{j\le k}P_j\le 50$；第 $k+1$ 个词起整词丢弃，记录丢弃词数 / 词元数（`truncated_words/truncated_tokens`） |
| 特征 | 最后一层隐状态 `last_hidden_state`，位置 $i<L$ 取原值，填充位置整行置 0 |
| `text_bert` | $(3,50)$ int64：`input_ids`、`attention_mask`（前 $L$ 个为 1）、`token_type_ids`（全 0） |
| 有效长度 | $L$ = 词元数（含 `[CLS]`、`[SEP]`）= 掩码和 |

说明：标点粘在词上时（如 `movie,`），BERT 会把标点切成独立词元，但它仍属于该词，共用该词的时间区间。整词截断保证每个保留词元都能对应到完整的词级时间区间。

## 4 语音特征（74 维，100 Hz）

**预处理**：`ffmpeg -ac 1 -ar 16000` 解码为 16 kHz 单声道 float32（多声道取平均）。
**分帧**：窗长 $N_w=400$（25 ms）、帧移 $H=160$（10 ms）、Hann 窗、$N_{\rm fft}=512$（补零）、`center=True`；第 $k$ 帧中心时刻 $\tau_k=kH/s_r=0.01k$ 秒，帧数 $T=1+\lfloor N/H\rfloor$（$N$ 为样点数）。$X_k(f)$ 为第 $k$ 帧 STFT，频点间隔 $\Delta f=31.25$ Hz。

维度布局仿照 CMU-MOSEI 所用 COVAREP 74 维的**分组结构**（11 维韵律/音质 + 25 + 25 + 13）：第 0、1 维（F0、VUV）与 COVAREP 同义，H1−H2 同名（但未做共振峰校正）；其余为可用开源库复现的替代量（COVAREP 的 NAQ/QOQ/PSP/MDQ 等依赖声门逆滤波的 MATLAB 实现，MCEP/HMPDM/HMPDD 以 MFCC/ΔMFCC/Δ²MFCC 代替）。**附件2 的 74 维数值与本文特征不可互换**（题面亦声明不对附件2 每一维的物理含义作假定）。

| 维 | 名称 | 定义（与代码一致） |
|---|---|---|
| 0 | F0（Hz） | pYIN（librosa.pyin）：$f_{\min}=65$、$f_{\max}=500$ Hz，分析帧 1024 点（64 ms，需覆盖两个最低基频周期）、帧移 160、`center=True`，其余为 librosa 默认（分辨率 0.1 半音、阈值数 100、Beta(2,18)、切换概率 0.01）；清音/静音帧取 0 |
| 1 | VUV | pYIN 浊音判决（0/1） |
| 2 | 浊音概率 | pYIN `voiced_prob` |
| 3 | 对数能量（dB） | $20\log_{10}\max(\mathrm{RMS}_k,10^{-5})$，$\mathrm{RMS}_k$ 为以 $\tau_k$ 为中心的 400 点矩形帧均方根；下限 −100 dB 保证静音帧也不是零行 |
| 4 | 过零率 | 400 点帧内符号变化比例（librosa.zero_crossing_rate） |
| 5 | 谱质心（Hz） | $\sum_f f|X_k(f)|/\sum_f|X_k(f)|$ |
| 6 | 谱带宽（Hz） | $\big(\sum_f \bar{X}_k(f)(f-c_k)^2\big)^{1/2}$，$\bar X_k$ 为按帧归一化的幅度谱，$c_k$ 为谱质心 |
| 7 | 85% 滚降频率（Hz） | 最小的 $f$ 使 $\sum_{f'\le f}|X_k(f')|\ge 0.85\sum_{f'}|X_k(f')|$ |
| 8 | 谱平坦度 | $\exp\big(\overline{\ln P}\big)/\overline{P}$，$P=\max(|X_k|^2,10^{-10})$ |
| 9 | H1−H2（dB） | 浊音帧：$H_h=20\log_{10}\max_{|f-hF_0|\le\delta}|X_k(f)|$，$\delta=\max(\Delta f,0.15F_0)$，取 $H_1-H_2$；清音帧取 0 |
| 10 | 谱倾斜（dB/kHz） | 对 1…256 号频点（31.25 Hz–8 kHz）做最小二乘直线拟合 $20\log_{10}\max(|X_k(f)|,10^{-10})=a+b\cdot f/1000$，取斜率 $b$ |
| 11–35 | MFCC 0–24 | 功率谱 $|X_k|^2$ → 40 个 Slaney Mel 滤波器（0–8000 Hz）→ $10\log_{10}\max(\cdot,10^{-10})$（**不做**逐片段 80 dB 截断，否则取值依赖片段最大值）→ DCT-II（正交归一）取前 25 维 |
| 36–60 | ΔMFCC 0–24 | `librosa.feature.delta(width=9, order=1)`（Savitzky–Golay 一阶导，边界 `interp`） |
| 61–73 | Δ²MFCC 0–12 | `librosa.feature.delta(width=9, order=2)`，只取 MFCC0–12 |

帧数不足 9 时差分窗取不超过帧数的最大奇数；不足 3 帧时差分置 0。所有非有限值置 0。
**零行语义**：真实存在的音频帧永远是非零行（能量下限 −100 dB、MFCC0 恒非零），只有序列填充位置整行为 0。

## 5 视觉特征（35 维）

**工具**：MediaPipe FaceLandmarker（tasks API，`RunningMode.VIDEO`，`num_faces=1`，`output_face_blendshapes=True`，检测/存在/跟踪置信度阈值均 0.5），模型文件 `q1/models/face_landmarker.task`（3.7 MB，Apache-2.0）。逐帧处理（`vision.sample_fps: null`），帧 $n$ 的时间戳 $t_n=n/\mathrm{fps}$；每个视频新建一个检测器（VIDEO 模式跨帧跟踪，不同视频不能共享跟踪状态）。

**布局**：采用 OpenFace 2.0 的 AU 输出布局——17 个强度（`AUxx_r`）+ 18 个出现标志（`AUxx_c`）= 35 维。选择它是因为每一维语义清楚，且维数与附件2 一致。注意：公开 CMU-MOSEI 流程中的 35 维视觉特征一般认为来自商业软件 Emotient FACET 4.2（已停止提供），题面也声明不对附件2 每一维的含义作假定；**本文 35 维与附件2 只是维数相同，数值不可互换**（问题2/3 的模型只用附件2 训练，不受影响）。

强度 $r_{\rm AU}=5\cdot\mathrm{clip}(s_{\rm AU},0,1)$（0–5 尺度），出现 $c_{\rm AU}=\mathbb 1[r_{\rm AU}\ge\theta]$，$\theta=1.0$（即 $s\ge0.2$）。$s_{\rm AU}$ 由 blendshape 分数（0–1）按下表得到，左右成对者取平均：

| 维（强度） | 维（出现） | AU | FACS 名称 | $s_{\rm AU}$ |
|---|---|---|---|---|
| 0 | 17 | AU01 | 内眉上扬 | browInnerUp |
| 1 | 18 | AU02 | 外眉上扬 | mean(browOuterUpLeft, browOuterUpRight) |
| 2 | 19 | AU04 | 皱眉 | mean(browDownLeft, browDownRight) |
| 3 | 20 | AU05 | 上睑提升 | mean(eyeWideLeft, eyeWideRight) |
| 4 | 21 | AU06 | 脸颊上提 | mean(cheekSquintLeft, cheekSquintRight) |
| 5 | 22 | AU07 | 眼睑收紧 | mean(eyeSquintLeft, eyeSquintRight) |
| 6 | 23 | AU09 | 皱鼻 | mean(noseSneerLeft, noseSneerRight) |
| 7 | 24 | AU10 | 上唇提升 | mean(mouthUpperUpLeft, mouthUpperUpRight) |
| 8 | 25 | AU12 | 嘴角上扬 | mean(mouthSmileLeft, mouthSmileRight) |
| 9 | 26 | AU14 | 酒窝 | mean(mouthDimpleLeft, mouthDimpleRight) |
| 10 | 27 | AU15 | 嘴角下压 | mean(mouthFrownLeft, mouthFrownRight) |
| 11 | 28 | AU17 | 下巴上抬 | mouthShrugLower |
| 12 | 29 | AU20 | 嘴唇横拉 | mean(mouthStretchLeft, mouthStretchRight) |
| 13 | 30 | AU23 | 嘴唇收紧 | mean(mouthPressLeft, mouthPressRight) |
| 14 | 31 | AU25 | 双唇分开 | $\mathrm{clip}\big(g\cdot\max(\text{jawOpen}-\text{mouthClose},\ \mathrm{mean}(\text{mouthLowerDownLeft/Right})),0,1\big)$，$g=2$ |
| 15 | 32 | AU26 | 下颌下降 | jawOpen |
| — | 33 | AU28 | 吸唇（仅出现） | mean(mouthRollLower, mouthRollUpper) |
| 16 | 34 | AU45 | 眨眼 | mean(eyeBlinkLeft, eyeBlinkRight) |

AU25 的理由：ARKit 规范中 `mouthClose` 是"下颌张开而双唇仍闭合"的矫正量，故 jawOpen − mouthClose 才表示"下颌张开且唇也分开"；不动下颌时靠下唇下拉也能分开双唇，故再与 mouthLowerDown 取大。不用 1 − mouthClose：自然闭嘴时 mouthClose≈0，会把闭唇误判为完全张开。增益 $g=2$：唇缝在下颌略张开时即可见，而 AU26 直接用 jawOpen 表示开度。

**未检出人脸的帧 → 35 维整行为 0**（与 `common.data` "整行为 0 = 不可用"的约定一致），记录人脸检出率 = 检出帧数 / 处理帧数。

**小脸重试**（`vision.crop_retry: true`，`crop_retry_below: 0.8`）：FaceLandmarker 的人脸检测器（BlazeFace 短距模型，输入 128×128）按长边缩放整帧，远景 16:9 画面中的小脸会漏检（跟踪只有在首次检出后才开始）。若整帧处理的检出率 < 0.8，则对**整段视频**改用居中正方形裁剪（边长 $\min(H,W)$）再处理一遍，保留检出率更高的一遍，记录所用的一遍（清单列 `vision_pass`、`face_detect_rate_full`）。整段只用一种输入，不逐帧混用——实测同一帧整帧与裁剪输入的 blendshape 可相差 0.2 以上，逐帧混用会引入口径跳变。裁剪不改变时间戳；blendshape 是表情系数，与坐标无关。

## 6 跨模态时序对齐模型

### 6.1 词级时间戳（`q1/align.py`）

对**给定转写文本**做强制对齐（不做识别、不改文本），词表 = 转写按空白切分的词（与第 3 节同一套下标）。

**(a) CTC 强制对齐（首选，`align.method: auto|ctc`）**。模型 `facebook/wav2vec2-base-960h`（LibriSpeech 960 h 微调的字符级 CTC，32 个符号，帧移 20 ms，输入零均值单位方差归一化）给出逐帧对数后验 $E\in\mathbb R^{T\times C}$。

* 文本规范化：大写，只保留 A–Z 与撇号；词间插入分隔符 `|`。含数字的词（如 `2019`、`3rd`）及规范化后为空的词不进入目标序列（读音与拼写无关），其时间由插值给出（见下）。
* 目标序列 $y_{1..U}$，扩展序列 $z=(b,y_1,b,y_2,\dots,b,y_U,b)$，长 $S=2U+1$，$b$ 为空白（pad）符号。
* Viterbi 动态规划（自写，numpy 实现；不用 `torchaudio.functional.forced_align`，该函数已宣布移除）：
  $$\delta_0(0)=E_{0,b},\quad \delta_0(1)=E_{0,y_1},\quad \delta_0(s)=-\infty\ (s\ge2)$$
  $$\delta_t(s)=E_{t,z_s}+\max\{\delta_{t-1}(s),\ \delta_{t-1}(s-1),\ \delta_{t-1}(s-2)\cdot\mathbb 1[z_s\ne b\wedge z_s\ne z_{s-2}]\}$$
  终点 $\arg\max\{\delta_{T-1}(S-1),\delta_{T-1}(S-2)\}$，回溯得到每帧的状态 $s_t$。可行性要求 $T\ge U+\#\{u:y_u=y_{u-1}\}$，否则该条样本回退到 (b)。
* 词区间：词 $w$ 的首字符第一次出现的帧 $f_0$、末字符最后一次出现的帧 $f_1$，$[S_w,E_w)=[0.02f_0,\ 0.02(f_1+1))$，截断到 $[0,D_a]$。置信度 = 该词字符帧上目标符号后验的平均值（`score`）。
* 插值：未进入目标序列的连续 $m$ 个词，在前一已定位词的终点 $l$ 与后一已定位词的起点 $r$ 之间均分：第 $q$ 个词占 $[l+(r-l)q/m,\ l+(r-l)(q+1)/m)$（`source=interp`）；位于开头/结尾时 $l=0$ / $r=D_a$。

**(b) VAD 比例回退（`vad_proportional`）**：CTC 模型无法加载时（`auto` 模式，日志与 `run_info.json` 写明原因），或单条 CTC 失败时使用。

* 能量 VAD：`librosa.effects.split(top_db=30, frame_length=400, hop_length=160)`，RMS 低于"全片最大 RMS − 30 dB"的帧为静音，得到有声段 $[a_k,b_k)$，$k=1..K$（无有声段时视整段为有声）。
* 拼接有声轴：$\mathrm{cum}_k=\sum_{i<k}(b_i-a_i)$，总长 $V$。词权重 $c_j=\max(1,\text{字母数字个数})$，累计位置 $C_j=V\sum_{i<j}c_i/\sum_i c_i$。
* 词 $j$ 占有声轴上的 $[C_j,C_{j+1}]$，逐段平移回真实时间（第 $k$ 段：$t=a_k+c-\mathrm{cum}_k$）；若它跨越段边界（跨一个停顿），**只保留与各有声段交集最长的那一段**——一个词不应覆盖停顿。得到的词区间有序、互不重叠、都在有声段内。
* 该方法只保证"词落在有语音的地方、按长度比例排开"，精度远低于 CTC，仅作回退。

**(c) 统一后处理**：$s_j\leftarrow\max(s_j,e_{j-1})$，$e_j\leftarrow\max(e_j,s_j)$，并截断到 $[0,D_a]$，保证单调；保留 4 位小数。

### 6.2 对齐版本（aligned，50 个共享位置）

记 $D_a$ = 音频时长（样点数/16000），$D_v$ = 视频时长（解码帧数/fps）。语音帧 $a_k\in\mathbb R^{74}$ 于 $\tau_k=0.01k$；视频帧 $v_n\in\mathbb R^{35}$ 于 $t_n=n/\mathrm{fps}$，人脸标志 $h_n\in\{0,1\}$。

**位置 $i$ ↔ 文本第 $i$ 个词元**，其时间区间 $I_i=[s_i,e_i)$：

* $i=0$（`[CLS]`）与 $i=L-1$（`[SEP]`）：整段 $[0,D_m]$（$m$ 为语音或视觉，各用自己的时长）——句级词元取全片段均值，两者特征相同；
* 词元 $i$ 属于第 $j$ 个词（区间 $[S_j,E_j)$），是该词 $P_j$ 个词元中的第 $r$ 个（$r=0..P_j-1$）：
  $$s_i=S_j+(E_j-S_j)\frac{r}{P_j},\qquad e_i=S_j+(E_j-S_j)\frac{r+1}{P_j}$$
  （词区间在其词元间均分）；
* $i\ge L$（填充）：三模态整行为 0。

池化：
$$F_i=\{k:\tau_k\in[s_i,e_i)\},\qquad A_i=\frac1{|F_i|}\sum_{k\in F_i}a_k$$
$$G_i=\{n:t_n\in[s_i,e_i)\},\qquad V_i=\begin{cases}\dfrac{1}{|G_i^{+}|}\sum_{n\in G_i^{+}}v_n,& G_i^{+}=\{n\in G_i:h_n=1\}\ne\varnothing\\ \mathbf 0,&G_i^{+}=\varnothing\end{cases}$$
* 区间短于帧间隔、$F_i$ 或 $G_i$ 为空时，取离区间中点最近的一帧（记录 `rule=nearest`）；
* 区间终点等于片段终点时闭到右端（不漏掉最后一帧）；
* 长度：`audio_lengths = vision_lengths = L`（位置共享）。语音在 $[0,L)$ 内恒为非零行；视觉零行 ⇔ 该位置区间内没有检出人脸的帧（天然缺失，与 `common.data` 的缺失语义一致）。

**与任务原设计的差异（有意修改）**：原设计让 `[SEP]` 位置的语音/视觉为 0 行。但对齐版文件没有独立的语音/视觉长度时，读取接口按文本掩码推断有效长度，`[SEP]` 处的人为 0 行会被统计成"缺失"，污染缺失分析。故把 `[SEP]` 与 `[CLS]` 同样对应整段，并在对齐版中也写出 `audio_lengths = vision_lengths = L`。

### 6.3 非对齐版本（unaligned，80 ms 栅格）

* 栅格 $\Delta=0.08$ s（12.5 Hz），位置 $k\leftrightarrow[k\Delta,(k+1)\Delta)$；$K_a=\lceil D_a/\Delta\rceil$，$K_v=\lceil D_v/\Delta\rceil$，上限 500（$500\times0.08=40$ s $>$ 最长片段 34.567 s，理论上不会截断；超出时截断并记录）。
* 帧到位置：$p(\tau)=\min(\lfloor\tau/\Delta\rfloor,K-1)$。语音位置 $k$ = 落入该位置的 100 Hz 帧均值（恰为 8 帧，末位置可能更少）；视觉位置 $k$ = 落入该位置的人脸帧均值；该位置没有任何帧（仅当 fps < 12.5 或抽帧时）→ 取最近帧；有帧但都无人脸 → 0 行。
* `audio_lengths` $=K_a$，`vision_lengths` $=K_v$，$k\ge K$ 为填充 0 行（后填充）。文本部分与对齐版相同。
* 选 80 ms 的理由：语音、视觉共用同一栅格 → 同一下标即同一时间段，位置→时间映射是确定的（$t=0.08k$），便于问题3 把证据位置回看到原始素材；且最长片段只需 433 个位置，满足附件2 的 500 上限。

### 6.4 对齐记录（`alignment/<id>.json`）

每条样本一个 JSON，把每个序列位置映射回原始素材：

| 字段 | 内容 |
|---|---|
| `id, video_id, clip_id, file, excel_row` | 样本编号、相对路径、标注表行号 |
| `durations_s` | `container`（ffmpeg 容器时长）、`audio`（$D_a$）、`video`（$D_v$） |
| `fps, n_video_frames_decoded` | 帧率、实际解码帧数 |
| `audio_frame` | `hop_s=0.01, win_s=0.025`，第 $k$ 帧时间 = $0.01k$（帧中心），`n_frames` |
| `video_frame` | 第 $n$ 帧时间 = $n$/fps，处理帧数、人脸帧数、检出率、所用一遍（full / center_square） |
| `voiced_intervals_s` | VAD 有声段 |
| `aligner` | 请求的/实际使用的对齐方法、模型、回退原因 |
| `words[]` | 每个词：`index, word, start, end, source(ctc/interp/vad_proportional), score` |
| `text` | 原文、`text_len`、词数、保留词数、截断词/词元数、词元列表、每词词元数 |
| `aligned.positions[]`（50 项） | `pos, token, token_id, word_index, word, rule(special_whole_clip/word_piece/pad), start_s, end_s, audio_frames=[k0,k1), audio_rule, video_frames=[n0,n1)`（原视频帧号），`n_video_frames, n_face_frames, vision_rule` |
| `unaligned.audio / .vision` | 列式数组（长度 = $K$）：`start_s, end_s, frame_start, frame_end`（半开区间，视觉为原视频帧号），`n_frames, n_used, rule`；`length, length_untruncated, truncated_s` |
| `lengths` | text / aligned_audio / aligned_vision / unaligned_audio / unaligned_vision |
| `status, errors, warnings` | 处理状态 |

## 7 异常与边界情况的处理规则（样本一律保留）

| 情况 | 处理 |
|---|---|
| 转写超长（词元 > 48） | 整词截断，记录 `truncated_words / truncated_tokens`，status=warning |
| 转写为空 | 只有 `[CLS][SEP]`（$L=2$），两者对应整段 |
| 词含数字 / 无字母 | 不参与 CTC，时间插值（`source=interp`） |
| 片段极短、区间短于帧间隔 | 取最近帧（`rule=nearest`） |
| 未检出人脸的帧 | 35 维整行 0；词元/栅格内全无人脸 → 该位置 0 行；检出率 < 0.5 记 warning |
| 整帧检出率 < 0.8 | 整段改用居中正方形裁剪重跑，取检出率高者（记 warning） |
| 无音轨 | 语音全 0、长度 0；词按字符数比例铺满视频时长（`no_audio_uniform`） |
| 音视频时长相差 > 0.2 s | 记 warning（两条流各用自己的时长） |
| 非对齐位置 > 500 | 截断到 500，记录截断秒数（附件1 理论上不会发生） |
| 文件缺失 / 无法解码 | 该样本（或该模态）全 0、长度 0，status=error，写明原因；不中断 |
| annotation 与 label 推出类别不一致 | 原样保留，只记录 |

## 9 核验（`q1/verify.py`）

输出 `verification_report.json/.md`，任一项不通过时退出码为 1。核验项：

1. 标注行 → 视频文件（每行都能找到文件）；视频文件 → 标注行（根目录下没有表外视频）；样本编号唯一。
2. 两份特征文件存在、顶层键为 `all`；`id` 与标注行**逐条、同顺序**相等；manifest 行、对齐记录文件与样本一一对应。
3. 字段齐全、形状与 dtype 正确；无 NaN/Inf。
4. 文本：掩码是前缀连续的 1，掩码和 = 记录的 `text_len` = 文本非零行数；`token_type_ids` 全 0；`input_ids` 与对齐记录一致；两版 `text_bert` 相同。
5. 对齐版：`audio_lengths = vision_lengths = text_len`；有效长度外全 0；语音有效范围内无 0 行；视觉非零位置 ⇔ 记录中该位置有人脸帧。
6. 非对齐版：长度 $=\min(500,\lceil D/0.08\rceil)$ 且与记录一致；有效长度外全 0；视觉非零位置 ⇔ 栅格内有人脸帧。
7. 词级时间戳单调、落在 $[0,D]$；词元区间单调且不越界；词数 = 转写词数。
8. `regression_labels / annotations / raw_text` 与标注表逐条相等，`classification_labels = reg_to_cls(label)`（不一致的 annotation 只统计）。
9. 视频文件 MD5 与提取时一致。
10. 无 `status=error` 的样本。
11. `common.data.load_all_splits` 能读取两份文件，版本识别正确，非对齐语音长度与文件一致。

**完整运行流程**（项目根目录下）：

