# 开发约定（各模块之间的接口合同）

> 给写代码的人看的。论文、说明文档里的说法必须和这里、和代码一致。

## 0. 运行环境

- 所有命令都在项目根目录 `研赛2026E_多模态情感预测/` 下以模块方式运行：`python -m q2.train --config configs/q2.yaml`。
- 赛题附件放在 `data/`（不入库）：
  ```
  data/附件1/<video_id>/<clip_id>.mp4   data/附件1/label-100.xlsx
  data/附件2/aligned_50.pkl  data/附件2/unaligned_50.pkl
  data/附件3/…pkl            data/附件4/…pkl + 原始视频
  ```
  附件3/4 的文件名未知 → 一律通过命令行参数 / 配置文件给路径，不写死。
- 运行产物统一写到 `outputs/<q1|q2|q3>/<run_name>/`（不入库）。
- 合成数据（只用于跑通代码，**数值不得进论文**）：`python -m common.synth --out outputs/synthetic --version aligned|unaligned`
  生成 `outputs/synthetic/附件{2,3,4}/{aligned,unaligned}_50.pkl`、附件4 视频、以及 `_truth_*.json` 真值。

## 1. 公共模块（已完成，只能调用，改动要同步所有使用方）

| 模块 | 内容 |
|---|---|
| `common/data.py` | `load_split / load_all_splits / get_split` → `SplitData`（feats/avail/valid/lengths/y_reg/y_cls/raw_text/ids/extra）；`Normalizer`（只用训练集可用位置拟合，不可用位置保持 0）；`reg_to_cls`（题面定义：y<0→0 Negative，y=0→1 Neutral，y>0→2 Positive）；`split_id`；常量 `MODALITIES / FEAT_DIMS / CLASS_NAMES / MOD_CN / CLASS_CN` |
| `common/missing.py` | `sample_spans / MissingSpec / make_drop_masks / apply_drop / simulate_missing / protocol_spec(combo, ratio, position, n_spans)`；训练增广 `AugmentConfig + random_drop_for_sample`；附件3 检测 `missing_statistics`；`MODALITY_COMBOS`（T/A/V/TA/TV/AV/TAV）、`POSITIONS`（head/middle/tail） |
| `common/metrics.py` | `evaluate_all(y_reg_true, y_reg_pred, y_cls_pred)` → acc3 / f1_weighted / f1_macro / mae / corr + acc2_has0 / acc2_non0 / acc7 / confusion；`composite_score`（验证集选模型）；`MAIN_KEYS / EXTRA_KEYS / flat_row` |
| `common/layers.py` | `ModalityEncoder`（投影→[MISS] 占位→时间编码→卷积→Transformer，只以可用位置为 key）、`MaskedAttentionPool`、`relative_time`、`safe_key_mask`、`masked_mean` |
| `common/torch_data.py` | `make_loader(sd, batch_size, shuffle, augment, seed)`；batch 字典键：`x_m / avail_m / valid_m / drop_m / offset_m / y_reg / y_cls / index`；`apply_drop_tensors(batch)`；`to_device` |
| `common/utils.py` | `set_seed / get_device / get_logger / dump_json / load_json / env_info / ROOT / DATA_DIR / OUTPUT_DIR` |

掩码语义：`avail`=该行特征非零（文本还要在 BERT 掩码内）；`valid`=名义有效范围；缺失=`valid & ~avail`。
填充、赛题置零、原始天然零行对模型一视同仁都是"不可用"。

## 2. 标签与输出一致性

- 训练/评测的类别一律用 `reg_to_cls(y)`（题面定义）。文件自带 `classification_labels` 只做一致性核对（`label_consistency_report`）。
- 对外输出（CSV）的极性与强度必须**自洽**：极性=分类头（加验证集上选定的偏置）的 argmax；
  强度做一致性投影：Negative → `min(ŷ, -0.01)`，Positive → `max(ŷ, 0.01)`，Neutral → `0`。原始回归值另列 `raw_intensity`。
  验证集上同时报告"投影前 / 投影后"两套指标，论文里说明取舍。
- 指标：主表 `acc3, f1_weighted, f1_macro, mae, corr`；补充 `acc2_has0, acc2_non0, acc7`。

## 3. 各问题的输出文件合同（论文生成脚本按这些文件名读取）

### 问题1 `outputs/q1/<run>/`
- `features/aligned_100.pkl(.gz)`、`features/unaligned_100.pkl(.gz)`：与附件2 同构（顶层键 `all`，字段 id/raw_text/text/text_bert/audio/vision/audio_lengths/vision_lengths/regression_labels/annotations/classification_labels）
- `alignment/<video_id>$_$<clip_id>.json`：逐位置对齐记录
- `manifest.csv / manifest.xlsx`：100 行宽表；`manifest_long.csv`：样本×模态长表（样本编号、模态类型、原始有效时长、特征维度、对齐粒度、序列长度…）
- `verification_report.json / .md`：一一对应、形状、时间单调性等核验结果
- `run_info.json`：环境、工具版本、全部参数；`logs/extract.log`
- `figures/typical_<id>.png`：典型样本对齐可视化

### 问题2 `outputs/q2/<run>/`
- `model.pt`（state_dict + normalizer + config + 决策偏置）、`config.yaml`、`train_log.csv`
- `metrics_valid.json`、`metrics_test.json`（完整输入 + 混合缺失协议，含投影前后）
- `missing_type_ratio.csv`（combo×ratio×seed 平均）、`missing_position.csv`、`missing_fragmentation.csv`、`degradation_fit.json`
- `ablation.csv`、`error_analysis.json`、`figures/*.png`
- `附件3_预测结果.csv`、`附件3_summary.json`

### 问题3 `outputs/q3/<run>/`
- `model.pt`、`config.yaml`、`train_log.csv`、`metrics_valid.json`、`metrics_test.json`
- `faithfulness.json`（删除/保留检验、内置贡献与积分梯度/Shapley 的一致性）
- `cards/<id>.png`（解释卡）、`figures/*.png`
- `附件4_预测与解释结果.csv`、`附件4_explanations.json`（逐位置重要性，便于复核）、`附件4_summary.json`
- `error_analysis.json`

## 4. 代码风格

- 中文注释 / docstring，风格同 `common/`；argparse 命令行；配置放 `configs/*.yaml`，命令行可覆盖。
- 随机性全部走种子（`set_seed`、`np.random.default_rng(seed)`）；评测用的缺失掩码固定种子，对所有模型相同。
- 不引入任何外部情感数据；预训练模型只用于问题1 的特征提取。
