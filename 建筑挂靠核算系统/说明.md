## 四、三张汇总表和各家明细现在完全对得上

你说「单位项目、项目汇总、单位项目明细这些界面出的数据应该都要与现在各个明细一致」——
查出两个原因：

**1）已收成本票被算了两遍。** 【项目汇总】【单位项目明细】里这一格的公式是
「成本票 + 收票方是某某的销项票」，而按项目取数时收票方条件写成了 `*`（任意非空）。
每一张销项票都有收票方，于是**全部销项票又被当成本票加了一遍**——整整翻一倍。
A001 的 1,022,642.12 就 = 成本票 531,241.12 + 销项开票 491,401。

**2）三张表的取数口径本来就不一样。** 汇总表按「开票方 / 收票方」，
8 张竖版明细按「归属单位表」（这一笔算在原对账明细的哪一张表上）。

# 上一轮改了什么（存档）

## 一、单位档案：一家单位可以配两档费率

原来每家只有一个「默认管理费率」，装不下你说的两种情况。现在每家有 **默认档** 和 **第二档**，各带自己的管理费率和返现率：

| 单位 | 默认档 | 第二档 |
|---|---|---|
| **金沁** | 框架合同 **5%** | 劳务合同 **3%** |
| **德誉嘉** | 扣 **8%**、其中 **4% 返现金** | 2026-7-22 起改成直接扣 **4%** 不返现 |

哪个项目走哪一档，由【项目档案】的「合同类型 / 费率档」决定：合同类型选“劳务合同”自动跳到第二档，也可以手动指定。单笔谈了别的价，还是直接在【业务流水】那一格盖掉。

历史数据没有按档位重算，而是**照原表逐笔写死的实际费率** —— 8 家单位的「应扣管理费」合计与原表八张表的合计行**逐家一分不差**（见【对账核对】新增的 8 行）。
顺带查出并修掉了一处口径错误：原来那 33 笔原表管理费为 0 的票（康欣老项目只过票不收费等），系统会按档案默认率补算，把管理费虚增了 26,851.47 元、应到成本票同额少算。

## 二、项目档案 = 合同管理台账

合同台账并进【项目档案】，一个项目一行看完链条 + 合同：

`项目编号 · 全称 · 项目类型(自营/合伙) · 合同类型 · 费率档 · 业主 · 一级单位/费率 · 二级单位/费率 · 我方主体 · 合同编号 · 签订/开工/竣工日期 · 状态 · **合同金额** · **审计(结算)金额** · 审减额(自动) · 累计开票(自动) · 开票进度(自动) · 施工地址 · 校验 · 备注`

**「项目编号」那一列的下拉数据源原来接的是单位档案的单位名单** —— 这就是你说的“提取的数据源不对”。已经去掉下拉（项目编号本来就该手工编），改成校验列自动查重号、查漏填，重号标红。

合同金额和审计金额填进去以后，审减额、累计开票、开票进度三列自动出。

## 三、业务流水：加了往来款和票据类型

新增 5 种业务类型：

| 业务类型 | 什么时候用 |
|---|---|
| **其他应付发生** | 收到别人的过账款（迅驰过账），或确认欠合伙方的钱 |
| **其他应付扣税** | 这笔过账/合伙款里，我方已经代垫的税费，要从应付里扣掉 |
| **其他应付支付** | 真把钱转给对方了 |
| **其他应收收回** | 收到德誉嘉返的 4% 现金 |
| **工资扣抵** | 用工资表 / 代发工资顶掉的劳务成本，不再另开成本票 |

新增两列录入：**票据类型**（劳务票 / 土建票 / 安装票 / 机械设备票 / 材料票 / 其他）和**返现率**；新增自动列：成本归类、其他应收、其他应付、年度、末层标记。

| 项目 | 原表 | 系统 |
|---|---:|---:|
| 德誉嘉 返管理费 4%（其他应收） | 7,935.67 | 7,935.67 ✓ |
| 迅驰 过账应付工程款 | 42,073.33 | 42,073.33 ✓ |

## 四、发票缺口表（新）：劳务票差多少、机械票差多少

这是你说的「我开了多少票出去、劳务发票准备了多少、机械发票回来了多少还有多少没回来」。按项目一行：

`劳务票 应开 / 已开 / 工资扣抵 / 还差　｜　机械票 应开 / 已开 / 还差　｜　其他票 …　｜　合计还差 / 状态`

**应开** 的口径做了一处重要修正。原来【链条核算】按【项目档案】填的那一条链算，可是有 34 行业务的项目同时走了两三条挂靠链（比如平双线同时走华城、德誉嘉、迅驰），档案只能填一条，另外几条的「应开」就漏了、「已开」却全算，结果出现一堆假的「多开了」。
现在【业务流水】自动判一个「末层」标记：**这一行的开票方，在同一个项目上没有再从别人手里收到销项票 → 该由我方直接回成本票给他**。应开就取所有链条末层的合计，多链条不会算漏也不会算重。【链条核算】同步改成这个口径，并加了「工资扣抵」列，两张表的合计现在**分毫不差**（1,016,888.87）。

历史票据的劳务/机械归类：45 笔直接匹配原发票总台账的「发票类型」列；成本票 22 笔按「同项目、金额等于某张销项票的应开成本票」认亲继承；其余按项目名和单位规则推断。**票据类型是黄色录入列，推断不准的直接改，缺口表立刻跟着变。**

## 四之二、项目利润表（新）：自营和合伙分开算

一个项目一行，算这个工程到底赚了多少：

| | 口径 |
|---|---|
| **业主端开票额** | 只取「直接开给业主的那一层」的开票额。一个工程走几条挂靠链，就把几条的顶层加起来 —— 中间层（康欣开给金沁那种）不会重复计 |
| 减 各层管理费 | 这个项目上所有层级被扣掉的管理费 |
| 减 应提税费 | 按单位档案参数逐笔算出来的增值税＋附加＋印花＋所得（不管交没交） |
| 加 返现 | 德誉嘉扣 8% 里返回来的 4%，冲减成本 |
| **＝ 票面毛利 / 毛利率** | 这就是你原来那几张《项目统计表》里「利润」的算法 |
| 减 项目实际支出 | 【资金日记账】里记到这个项目名下的支出 |
| **＝ 项目净利** | |
| 减 应转他方 | 过账款、合伙项目要转给别人的（＝往来台账里该项目的其他应付发生额减我方代垫税费） |
| **＝ 归属我方利润** | |

**自营和合伙分开**：表头正下方三行小计 —— 全部合计 / 自营项目小计 / 合伙项目小计。合伙项目那一列底色是黄的，也可以直接按「项目类型」筛。目前：

| | 业主端开票额 | 票面毛利 | 毛利率 | 应转他方 | 归属我方 |
|---|---:|---:|---:|---:|---:|
| **全部** | 2,519,725 | 2,253,507 | 89.4% | 42,073 | **2,211,433** |
| 自营项目（54 个） | 1,924,929 | 1,730,908 | 89.9% | 42,073 | 1,688,834 |
| 合伙项目（9 个） | 594,796 | 522,599 | 87.9% | 0 | 522,599 |

两点要知道：

- **毛利率看着很高（89%）是因为「项目实际支出」现在是 0**。原日记账「项目」那一列填的是「铜梁项目」「光伏项目」「10kv少柏线池塘4社」这类工地/部门标注，不是项目编号，硬塞进项目编号列会跟项目档案对不上，所以导入时留空了。**在【资金日记账】D 列把项目编号选上，这一列立刻出数**，毛利率也就落到真实水平。合计行右边有一行动态提示盯着这件事。

日记账里记到项目名下、但费用类型是 **税费 / 管理费 / 借款 / 还借款 / 转备用金 / 其他应付支付 / 其他应收收回** 的不算工程成本 —— 要么已经在管理费和税费里算过一次，要么根本不是成本。
