# 电商一体化账务模板

拼多多/抖音/淘宝这类电商生意用的一套账：**业务登记 → 自动凭证 → 报表**，一条线打通。
录完采购、销售、返利、资金、费用，科目余额表和三张报表自己就出来了，
不用再手工录一遍总账；只有折旧、税费计提、正式往来抵销这几件事才走《手工凭证》。

| 文件 | 说明 |
|---|---|
| `电商一体化账务模板_2026.xlsx` | 模板本体，36 张表，一年一个账套 |
| `生成脚本/build_ec.py` | 一键生成整本工作簿 |
| `生成脚本/ec_data.py` | 档案与科目表等基础数据 |
| `生成脚本/ec_test.py` | TEST 测试案例数据 |
| `生成脚本/ec_style.py` | 样式常量 |

## 一之二、第二轮优化：内帐含税口径 + 大单量电商的四个实务问题

原版是按「不含税 + 税额」记的标准外帐口径。第二轮按实际用法改成**内帐含税口径**，
并针对「零售几十万行怎么办」「帮别人代发怎么记」这些真问题加了三张表。

### 1　全表含税，税不另列

进货、销售、返利、收入、成本、费用，一律按**实付实收的含税金额**记账，
不拆不含税和税额；科目表里删掉了「应交税费—应交增值税(进项税额/销项税额/进项税额转出)」。
实际缴出去的税在《资金流水》选「付-税费-增值税 / 附加 / 所得税 / 个税」，
对方科目直接是「税金及附加 / 所得税费用 / 应付职工薪酬」—— 缴多少进多少费用。

《发票台账》保留，但它只回答一件事：**这一单的票收齐了没有**。
金额填票面价税合计，税率那列是备查的，整张表一分钱都不进凭证。

凭证行数也跟着瘦了：采购 4 行 → 3 行，销售 7 行 → 6 行，代发 8 行 → 6 行，费用 3 行 → 2 行。

### 2　帮别人的店铺做一件代发 →《受托代发登记》

原来的《一件代发结算》是「我的店出单、别人帮我发货」。
新增的《受托代发登记》正好反过来：**别人的店出单、我发货**。

关键是每一行都要选一个【资金归属】：

| 资金归属 | 钱在谁账上 | 怎么记账 |
|---|---|---|
| **款到我司** | 终端买家的钱先进我们账户 | 《资金流水》记「收-代收货款」，**到账全额**（平台扣完佣金后的净额）整笔挂进「其他应付款—代收货款」；《受托代发登记》再把属于我的那块（供货额＋代发服务费）从代收货款转成收入；剩下的「应退委托方」欠着，结给它时记「付-代发结款」 |
| **款到委托方** | 买家的钱进委托店铺自己的账户 | 就是一笔普通应收账款，代收货款那一套完全不出现；委托方按期结我的供货款时记「收-代发服务费」 |

这样设计的意义：**几百万代收款不会虚增成收入**，利润表里只有我的供货价和服务费。
「其他应付款—代收货款」的余额就是还欠各委托店铺多少钱 ——
《综合往来对账》新增了「代收货款余额(欠委托方)」一列，《老板经营看板》也单列一行。

平台扣费（如果走我们的平台店）是从代收货款里扣的，实质由委托方承担，
所以它不进我们的损益，只是让「应退委托方」少一块；表里有「预计到账(代收−扣费)」给你跟流水对。

货是我们自己的，所以照样结转成本、照样减库存商品。
委托方欠我供货款、我又欠它代收货款，签了协议可以在《手工凭证》做
「借 其他应付款—代收货款／贷 应收账款」正式抵销，两边填代发单号，双边自动认。

### 3　拼多多/抖音批量结算、零售几十万行 →《平台结算单》

平台不是一单一单打钱，是按期整笔结算，中间还扣佣金、推广、运费。
零售条目几万几十万，明细**永远不要**往这套表里录。一个店一期在这张表录一行就够了：

- 销售货款、退款退货、平台佣金、推广/流量费、平台运费、其他扣费 → 自动算扣费合计和应结净额
- **【收入认定】= 结算单认收入** → 零售明细一行都不录，收入直接由这张结算单产生
  （借 应收账款＋销售费用／贷 主营业务收入），成本由《月末盘点与成本》整月倒轧
- **【收入认定】= 销售登记认收入** → 收入和扣费已经在《销售登记》记过了，
  这张结算单**不生成任何凭证**，纯当对账工具：右边自动把销售登记同店同期的金额拉过来比，
  差 1 块钱以上就亮红（预警 W26）

收入算在「结算期间止」那个月，不是算在平台打款那天 —— 6 月的单就是 6 月的收入。

对账只跟「客户 = 这个店的平台结算往来单位」的销售行比（《店铺档案》新增了这一列），
同一个店里的批发单、线下单不会掺进来搅乱对账。

**关于「手工录关联单号不现实」**：
平台把钱打过来时记一笔「收-平台结算」，关联单号填结算单号 —— 一个月一个店就这一笔。
而且关联单号本来就**可以不填**：不填的话钱照样按业务类型进对应科目、
《综合往来对账》按往来单位汇总照样准，只是单据级的核销跟不了而已。
零售那种一天几千单，本来就不该按单跟账。

另外加了一条硬提醒（预警 W29）：平台账单里**直接扣掉**的推广费只填结算单，
不要再去《费用及其他》登记一遍，否则销售费用翻倍。

### 4　销售成本不用手工录 →《查询设置》三选一 +《月末盘点与成本》兜底

《销售登记》删掉了「手工单位成本」那一列。成本怎么算由《查询设置》里一个开关统管全表：

| 方式 | 怎么算 | 适合谁 |
|---|---|---|
| **A 月加权平均**（默认） | 单位成本 = 截至这一单当天的加权平均实际采购成本（含期初库存），全自动 | 商品数不多、采购登记记得全 |
| **B 毛利率倒轧** | 单位成本 = 售价 ×（1 −《商品档案》里的目标毛利率） | ERP 数据不准、只要个大概数 |
| **C 月末盘点倒轧** | 登记页一分成本都不结转，整月成本 = 期初存货 ＋ 本月进货 − 月末实盘 | **每天发几千单、明细没法一笔笔算成本的** |

新增《月末盘点与成本》（按 公司 × 年月）是成本的**兜底出口**：
只要填了「实盘金额」，账面和实盘的差额就自动出一张「借 主营业务成本／贷 库存商品」的调整凭证。
实盘金额留空 = 这个月不盘点，不出任何凭证。

所以三种用法都成立：平时按 A 自动结转、季末盘一次纠偏；或者干脆选 C 全靠盘点；
零售走《平台结算单》认收入（没有销售明细、账面库存不会减）也是靠它把成本补上
（不盘就报警，预警 W28）。

期初账面存货是从各登记表按「年月 < 本月」直接滚出来的，中间某个月没建行也不会漏数。

实测：同一套数据下，成本方式 A 和 C 的**全年成本总额完全相同**（456,778.00），
只是构成不同 —— A 是「销售登记 206,200.75 ＋ 受托代发 56,040.56 ＋ 月末盘点 153,450.69」，
C 是「月末盘点 415,692.00」一家包办。

### 5　《销售登记》也可以按月汇总录

不用一单一行。一行可以是一笔大单，也可以是「这个店这个商品这个月的汇总」——
新增的「订单笔数」列填这行代表多少笔就行（《店铺利润分析》的笔数按它加总）。
所以三条录入路线可以按店混着用：

1. 单量小、要按单跟账 → 《销售登记》一单一行
2. 单量中等 → 《销售登记》按「店铺＋商品＋月」汇总录一行
3. 单量几万几十万 → 明细一行都不录，只录《平台结算单》

## 二、截图里那几条需求，分别落在哪

### 1　同一个资方既是供应商又是客户，还是资方

《往来单位主档》一家只建一个编码，右边四个「是否」勾上身份。
勾了供应商，采购登记的下拉里才有它；勾了客户，销售登记的下拉里才有它 —— 互不影响。

**账是分四条线记的**：

| 业务 | 走哪个科目 |
|---|---|
| 采购 | 应付账款 |
| 销售 | 应收账款 |
| 返利 | 其他应收款—应收返利 |
| 融资 | 短期借款 / 其他应付款—股东借款 |

《综合往来对账》按 **「公司 + 往来单位」** 汇总，四条线分四组列，最后才给
「经营净往来」和「净资金敞口」两个数给老板。
**甲公司欠宏发的钱，不会拿乙公司应收宏发的钱去冲** —— 同一家在多家公司都有余额时，
最右边会亮一条 ⚠ 提示。

测试数据里 **宏发供应链** 就是这种三重身份：
从它进货（应付）、把尾货卖给它（应收）、还向它借了 10 万周转（短期借款），
三笔在《综合往来对账》里清清楚楚分开列着。

### 2　往来抵销单独留出口

系统**不会**自动把应收应付抵掉。真要抵，去《手工凭证》做一张正式凭证：

```
借 应付账款（宏发）9,000    关联单号 CG2026009    用途标记「往来抵销」
    贷 应收账款（宏发）9,000    关联单号 XS2026012
```

填了「关联单号」以后，那张采购单的「已付/已结」和那张销售单的「已回/已结」
**双边都自动认这笔** —— 这就是测试数据 TEST03 演示的场景。

### 3　报表直接建在「业务登记 + 会计调整」上

《自动凭证》按固定规则把登记表展开成分录（金额是 0 的行自动隐去）：

| 来源 | 展开成 |
|---|---|
| 采购登记（4 行） | 借 库存商品＝实际采购成本；借 进项税；借 其他应收款—应收返利；贷 应付账款＝含税金额 |
| 销售登记（7 行） | 借 应收账款；贷 主营业务收入；贷 销项税；借 主营业务成本／贷 库存商品；借 销售费用／贷 应收账款（平台扣费） |
| 返利登记（2 行） | 只做「确认数 − 账面预提数」的差异调整，对冲主营业务成本 |
| 一件代发（8 行） | 销售三行同上；成本这边 借 主营业务成本＋借 进项税／贷 应付账款；再加平台扣费两行。**不碰库存商品** |
| 资金流水（2 行） | 借 账户科目／贷 对方科目（收钱），付钱反过来 |
| 费用及其他（2 行） | 借 借方科目（费用或资产）＝含税金额；贷 贷方科目（应付账款/应付职工薪酬/应交税费） |

> 以上是**第二轮改成含税口径后**的行数。此外还有：
> 受托代发 5 行、平台结算单 3 行（只有「结算单认收入」的才出）、月末盘点 2 行（填了实盘才出）。

《自动凭证》+《手工凭证》→《科目余额表》→ 三张报表。业务登记改一个数，报表立刻跟着变。

### 4　采购返利不重复计算

**实际采购成本 = 含税采购金额 − 应收返利。**

采购入库时就按净额进「库存商品」，返利单独挂「其他应收款—应收返利」：

```
借 库存商品            44,100.00   ← 含税 45,000.00 − 返利 900.00
借 其他应收款—应收返利     900.00
    贷 应付账款                    45,000.00
```

成本在入库时就已经降下来了，卖的时候按净成本结转，**所以返利不会在利润表里再算第二次**。

《返利登记》只干三件事：跟供应商对账确认金额、跟踪到账、跟踪发票。
你填的「确认返利金额」跟系统算的「账面应收返利」之间的差额才会生成凭证去调成本
（测试数据里有上调 +68、核减 −24、凭空 +500 三种差异场景）。

### 5　销售成本按实际采购单位成本结转

默认（成本方式 A）：单位成本 = **截至这一单当天**的加权平均实际采购成本（含期初库存），
销售成本 = 单位成本 × 本单数量。进了 1000 个只卖 300 个，就只转 300 个的成本。**全自动，不用手工填。**

第二轮改版后还可以选 B 毛利率倒轧、C 月末盘点倒轧，
并且不管选哪种，《月末盘点与成本》填了实盘金额都会自动把差额调成本 —— 详见「一之二、4」。
取不到成本（这个商品在这家公司名下没进过货、期初也没填）会被预警 W07 点名。

### 6　一年一个账套 + 统一查询设置

《查询设置》只有四个格子：**年度 / 公司 / 月份 / 销售成本怎么算**。
改前三个，利润表、资产负债表、现金流、综合往来、店铺利润、老板看板一起跟着换。

- 公司选「全部」＝合并看；选某一家＝只看那一家
- 月份选「全年」＝1-12 月累计；选某个月＝只看那个月的发生额，期初自动滚到上月末

换年度：复制文件 → 改年度 → 把上年《资产负债表》年末数抄进《期初余额》
（主区 + 右边三个明细小区：往来单位 / 商品库存 / 资金账户）→ 删掉上年的业务数据。

### 7　六张管理表

| 表 | 看什么 |
|---|---|
| 综合往来对账 | 按「公司+往来单位」的应付/应收/返利/借款四条线，净往来与净敞口 |
| 收付款核销中心 | **只列还没结清的单**，带逾期天数和账龄段（未到期/30 内/31-60/61-90/90 以上） |
| 店铺利润分析 | 自营和代发分开算毛利，减店铺直接费用＝店铺净利；公司共同费用单列不摊 |
| 商品库存与成本 | 每个商品（分公司）的年初、本年进销、结存数量与金额、当前单位成本 |

### 建过程中挖出来并修掉的坑

| 坑 | 后果 | 处理 |

| 固定资产双记 | 《费用及其他》已经借了固定资产，《资金规则》「付-购置固定资产」又借了一次 → 固定资产 33,929 翻倍、应付挂着不消 | 规则改成贷 应付账款，走「先登记后付款」的统一套路 |
| 工资挂错科目 | 费用登记贷 应付账款，付钱却冲 应付职工薪酬 → 两个科目各挂一笔 28,000 | 基础资料给每个费用项目加了「贷方科目」，工资挂应付职工薪酬、税费挂应交税费 |
| 代发单收付互相抵掉 | 一个结算单号既有收客户的钱又有付代发商的钱，净额算法把两边抵了 → 已回款 −4,400 | 「已回」只认「收-」开头的业务类型，「已付」只认「付-」开头的 |
| 退货行被当成付超/收超 | 采购退货含税 −2,200，未付自然是负数，被预警当成「已付大于应付」 | 规则加上「原单金额 > 0」的前提 |

| 借款单号被当成找不到业务单 | JKxxxx 本来就没有业务登记表 | W12 只查「本该对得上业务单」的那七类业务类型 |

### 一轮多维度审计（8 个维度并行 + 对抗性复核）又挖出来的

| 坑 | 后果 | 处理 |
|---|---|---|
| **内部转账被记了两遍** | 平台提现记两行（一出一入），每一行都按「借对方账户科目／贷本账户科目」展开成一张**完整**凭证 —— 银行存款和平台资金各虚增虚减 50,000 | 凭证只由「转出」那一行生成，「转入」行只用来让收款账户的余额动起来，不再出凭证 |
| **查询月份填成文本就全表归零** | C6 原来是文本格式又没下拉，照说明书手打一个「3」，`N("3")=0` → 起止年月变成 202600，**所有报表静默变 0，而 15 项勾稽仍然全 ✔** | 月份/公司都改成真下拉；所有取数改用 `IFERROR(VALUE(...))`，文本也认；另加一格「参数自检」，填错直接标红 |
| **返利「确认金额」留空＝全额冲销** | 留空被当成 0，差异＝0−账面＝−账面，系统立刻把预提的应收返利全冲掉、成本加回去 | 留空＝还没对账，差异留空不动账；状态显示「★ 待对账确认」。真的一分不给才填 0 |
| **手工凭证科目名写错，钱凭空消失** | 报表不动、勾稽全 ✔、预警一条不响（W17 原来只扫自动凭证） | W17 改成自动＋手工都扫；科目表的「报表项目」也加了下拉和合法值校验（W23） |
| **勾稽 J13 是个恒等式** | 两边其实是同一个公式，永远 ✔，等于没查 | 换成「利润表净利润 = 科目余额表全部损益类科目轧差」—— 真能抓出「报表项目填错」的科目；原来那条降级成 J16 分项自检 |
| **「损益结转」诱导用户做重复结转** | 本模板不做结转（未分配利润直接由利润表带出），可下拉里却有这个选项 | 从用途下拉里删掉，换成「存货调整/重分类」 |
| **预收货款被指向「收-其他」** | 而「收-其他」对方科目是营业外收入，会直接虚增利润 | 新增「收-预收货款」→ 预收账款；W06 的处理建议一并改掉 |
| **「付-税费」只对应增值税** | 缴附加税/个税/所得税会把已计提的负债永远挂在账上 | 拆成 增值税 / 附加 / 所得税 / 个税 四个业务类型，各挂各的科目 |
| **金额被粘成文本，整单静默消失** | 那一单不生成凭证、报表照样平，肉眼看不出来 | 新增 W21：逐列扫 ISTEXT，指出哪张表有文本金额和怎么转回数字 |
| **内部转账选了别家公司的账户** | 两行各自轧差，钱在两家账上同时消失 | 新增 W22：对方账户必须属于同一家公司 |
| **平台扣费有两条录入通道** | 销售登记的「平台扣费」列和费用项目里的「平台佣金」，都进销售费用，容易重复算 | 费用项目里删掉「平台佣金/技术服务费」，只留销售登记那一条路 |
| 收支互为相反数时整行凭证被抹掉 | 空行判断用的是 `借+贷=0` | 改成 `ABS(借)+ABS(贷)=0` |

## 七、注意

- **口径只有一条：全部含税。** 收入、成本、费用、应收应付，一律按实付实收的数记，不拆税额；
  缴出去的税直接进费用（《资金流水》选「付-税费-xx」）。《发票台账》只管票收齐没有，不进账。
- 平台账单里**直接扣掉**的推广费只填《平台结算单》，不要在《费用及其他》再登一遍（预警 W29 会抓）。
- **不要整行删除**登记表里的行（会把公式一起带走），清空浅黄格子即可。
- **不要用「另存为」转格式**，正常 Ctrl+S 保存没问题。
- 表比较大（26 万条公式），打开和重算会慢几秒，属正常。嫌慢可以把
  《自动凭证》和《_自动清单》尾部的空白行往上删一些（留出实际业务量一倍的余量）。
